# AWS Elastic Beanstalk vs. AWS App Runner: 백엔드 배포 가이드

이 문서는 Node.js 백엔드 애플리케이션을 AWS에 배포할 때 고려할 수 있는 두 가지 주요 서비스, Elastic Beanstalk와 App Runner의 장단점을 비교하고 각 서비스의 기본적인 배포 방법을 안내합니다.

---

## 1. AWS Elastic Beanstalk

### 가. Elastic Beanstalk란?

AWS Elastic Beanstalk는 애플리케이션을 실행하는 데 필요한 AWS 인프라를 자동으로 설정하고 관리해주는 오케스트레이션 서비스입니다. 코드만 업로드하면 용량 프로비저닝, 로드 밸런싱, 오토 스케일링, 애플리케이션 상태 모니터링에 대한 세부 정보를 처리합니다.

### 나. 장점 (Pros)

*   **높은 유연성 및 제어:** 기반 인프라(EC2 인스턴스 유형, 로드 밸런서, 데이터베이스 등)에 대한 세부적인 제어가 가능합니다.
*   **다양한 플랫폼 지원:** Node.js, Python, Java, .NET, Go, Ruby 등 다양한 언어와 플랫폼을 폭넓게 지원합니다.
*   **성숙한 서비스:** 오랫동안 검증된 서비스로, 풍부한 기능과 문서, 커뮤니티 지원을 제공합니다.
*   **VPC 통합:** 기존 Virtual Private Cloud(VPC) 내에 애플리케이션을 쉽게 배포할 수 있습니다.

### 다. 단점 (Cons)

*   **복잡한 초기 설정:** App Runner에 비해 설정해야 할 옵션이 많아 초기 구성이 복잡하게 느껴질 수 있습니다.
*   **느린 배포 속도:** 새로운 버전을 배포하거나 설정을 변경할 때 인프라를 업데이트해야 하므로 몇 분 이상 소요될 수 있습니다.
*   **비용 관리의 필요성:** 세부적인 제어가 가능한 만큼, 리소스를 효율적으로 관리하지 않으면 불필요한 비용이 발생할 수 있습니다.

### 라. 배포 방법 (How-to)

1.  **소스 코드 압축:**
    *   `server` 디렉토리로 이동합니다.
    *   `node_modules`와 `.gitignore`에 명시된 불필요한 파일을 제외한 모든 소스 코드와 `package.json` 파일을 `.zip` 파일로 압축합니다.

2.  **Elastic Beanstalk 환경 생성:**
    *   AWS Management Console에서 Elastic Beanstalk 서비스로 이동합니다.
    *   '새 애플리케이션 생성'을 클릭하고 애플리케이션 이름을 지정합니다.
    *   '환경 생성'을 선택하고 '웹 서버 환경'을 선택합니다.
    *   환경 이름, 도메인을 설정하고 플랫폼으로 **Node.js**를 선택합니다.
    *   '코드 업로드' 옵션을 선택하고, 위에서 생성한 `.zip` 파일을 업로드합니다.
    *   '환경 생성'을 클릭하여 배포를 시작합니다.

3.  **환경 변수 설정:**
    *   생성된 환경의 '구성' > '소프트웨어' > '환경 속성'으로 이동합니다.
    *   데이터베이스 연결 문자열, API 키 등 애플리케이션에 필요한 환경 변수를 추가합니다.

## 2. AWS App Runner

### 가. App Runner란?

AWS App Runner는 소스 코드 또는 컨테이너 이미지로부터 확장 가능하고 안전한 웹 애플리케이션을 쉽고 빠르게 배포할 수 있도록 하는 완전 관리형 서비스입니다. 인프라에 대해 거의 신경 쓸 필요 없이 애플리케이션을 즉시 실행할 수 있습니다.

### 나. 장점 (Pros)

*   **단순함과 속도:** 몇 번의 클릭만으로 소스 코드 저장소(예: GitHub) 또는 컨테이너 이미지에서 직접 배포가 가능하며, 배포 속도가 매우 빠릅니다.
*   **완전 관리형:** 서버, 클러스터, 오토 스케일링 정책 등을 관리할 필요가 없습니다. 트래픽에 따라 자동으로 스케일 인/아웃됩니다.
*   **비용 효율성:** 트래픽이 없을 때는 컴퓨팅 리소스를 일시 중지하여 비용을 절감할 수 있는 옵션을 제공합니다.
*   **컨테이너 최적화:** Docker 컨테이너 배포에 매우 적합하며, 컨테이너 오케스트레이션에 대한 지식이 필요 없습니다.

### 다. 단점 (Cons)

*   **제한적인 제어:** 기반 인프라에 대한 제어권이 거의 없습니다. 특정 EC2 인스턴스 유형을 선택하거나 로드 밸런서 설정을 세밀하게 조정할 수 없습니다.
*   **플랫폼 및 리전 제한:** Elastic Beanstalk에 비해 지원하는 런타임 및 리전이 제한적일 수 있습니다.
*   **VPC 통합의 제약:** 기존 VPC의 특정 서브넷에 배포하는 등의 복잡한 네트워킹 요구사항을 충족하기 어려울 수 있습니다. (최근 기능이 추가되었으나 여전히 제한적)

### 라. 배포 방법 (How-to)

1.  **소스 코드 준비:**
    *   GitHub과 같은 지원되는 소스 코드 저장소에 `server` 디렉토리의 코드를 푸시합니다.

2.  **App Runner 서비스 생성:**
    *   AWS Management Console에서 App Runner 서비스로 이동합니다.
    *   '서비스 생성'을 클릭합니다.
    *   **리포지토리 유형**으로 '소스 코드 리포지토리'를 선택하고, GitHub 계정을 연결한 후 해당 프로젝트의 리포지토리와 브랜치를 선택합니다.
    *   **배포 설정**에서 '자동'을 선택하면 코드가 푸시될 때마다 자동으로 배포됩니다.

3.  **빌드 및 실행 구성:**
    *   App Runner가 자동으로 `package.json`을 감지하고 빌드 및 실행 명령을 제안합니다. (일반적으로 `npm install`과 `npm start` 또는 `node server.js`).
    *   **포트**에 `server.js`에서 사용하는 포트 번호(예: `3001` 또는 `5000`)를 입력합니다.
    *   **환경 변수**가 필요하다면 이 단계에서 추가합니다.

4.  **검토 및 생성:**
    *   설정을 검토하고 '생성 및 배포'를 클릭하면 App Runner가 코드 빌드, 컨테이너화 및 배포를 자동으로 진행합니다.

---

## 3. 결론 및 추천

*   **AWS App Runner:** 빠른 개발 속도와 간편한 배포를 최우선으로 생각하는 경우, 또는 컨테이너 기반 워크플로우에 익숙한 경우에 이상적입니다. 스타트업이나 소규모 프로젝트, 마이크로서비스 아키텍처에 적합합니다.
*   **AWS Elastic Beanstalk:** 애플리케이션의 기반이 되는 인프라에 대한 세밀한 제어가 필요하거나, App Runner에서 지원하지 않는 특정 구성(예: 복잡한 네트워킹)이 요구되는 경우에 적합합니다. 더 복잡하고 규모가 큰 애플리케이션에 유리할 수 있습니다.

**이 프로젝트의 경우, 먼저 AWS App Runner로 시작하여 빠르게 배포하고 실행하는 것을 추천합니다.** 프로젝트가 성장하고 더 복잡한 인프라 요구사항이 생기면 그때 Elastic Beanstalk로 마이그레이션을 고려해볼 수 있습니다.
