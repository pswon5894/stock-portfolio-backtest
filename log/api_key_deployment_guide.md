# 배포 시 API 키 및 환경 변수 관리 가이드

이 문서는 로컬 개발 환경에서 `.env` 파일을 사용하여 관리하던 API 키와 같은 민감한 정보를 배포 환경(예: Render, Heroku)에서 어떻게 안전하게 처리하는지에 대해 설명합니다.

---

### 문제 상황: 왜 `.env` 파일은 Git에 포함되지 않는가?

사용자께서 정확히 파악하신 대로, `.env` 또는 `.dev` 같은 파일들은 민감한 정보(API 키, 데이터베이스 접속 정보 등)를 담고 있기 때문에 보안을 위해 `.gitignore`에 추가하여 Git 저장소(따라서 GitHub)에 올라가지 않도록 하는 것이 표준적인 방법입니다.

- **보안**: 만약 키가 GitHub에 공개되면, 누구나 악의적으로 사용자의 계정으로 API를 호출하여 금전적 손실이나 데이터 유출을 유발할 수 있습니다.
- **협업**: 팀원마다 다른 개발 환경(DB 정보 등)을 가질 수 있으므로, 환경 설정은 각자의 로컬 머신에만 두는 것이 좋습니다.

그렇다면 GitHub에 없는 이 정보들을 배포된 서버는 어떻게 알 수 있을까요?

---

### 해결책: 호스팅 플랫폼의 "환경 변수" 설정

해결책은 배포하려는 호스팅 플랫폼(Render, Heroku, Vercel, AWS 등)에서 제공하는 **환경 변수(Environment Variables)** 설정 기능을 사용하는 것입니다.

로컬 환경에서는 `dotenv` 라이브러리가 `.env` 파일에서 변수를 읽어 `process.env.API_KEY`와 같은 형태로 코드에 주입해줍니다.
배포 환경에서는 `.env` 파일이 없지만, 호스팅 플랫폼이 직접 시스템의 환경 변수로 똑같은 값들을 설정해줍니다. 따라서 코드는 **수정할 필요 없이** 양쪽 환경에서 동일하게 동작합니다.

---

### 단계별 해결 방법 (Render, Heroku 기준)

1.  **로컬 `.env` 파일 확인**: 먼저 로컬 프로젝트의 `server` 디렉토리에 있는 `.env` 파일의 내용을 확인합니다. 아래와 같은 형태일 것입니다.

    ```
    API_KEY=sk-abcdef1234567890
    DATABASE_URL=postgres://user:password@host:port/dbname
    ```

2.  **호스팅 플랫폼 대시보드 접속**: 사용하려는 서비스(예: Render)에 로그인하여 배포한 백엔드 애플리케이션의 대시보드로 이동합니다.

3.  **환경 변수 메뉴 찾기**:
    *   **Render**: 대시보드의 **[Environment]** 탭으로 이동합니다.
    *   **Heroku**: 대시보드의 **[Settings]** 탭에 있는 **[Config Vars]** 섹션으로 이동합니다.
    *   대부분의 플랫폼에서 "Environment", "ENV", "Secrets", "Config" 등의 이름으로 메뉴를 찾을 수 있습니다.

4.  **키-값 쌍 입력**: `.env` 파일에 있던 내용을 그대로 웹 대시보드의 입력란에 하나씩 추가합니다.

    -   `KEY` 입력란에 `API_KEY`를, `VALUE` 입력란에 `sk-abcdef1234567890`를 입력하고 추가합니다.
    -   `KEY` 입력란에 `DATABASE_URL`을, `VALUE` 입력란에 `postgres://...`를 입력하고 추가합니다.

    ![Render 환경 변수 설정 예시](https://render.com/images/docs/environment-variables-and-secrets.png)
    *(Render 공식 문서의 환경 변수 설정 화면 예시)*

5.  **재배포 및 확인**: 환경 변수를 모두 추가하고 저장하면, 보통 플랫폼이 자동으로 애플리케이션을 재시작하거나 재배포합니다. 이후 애플리케이션은 파일이 아닌 플랫폼이 주입해준 환경 변수를 읽어서 정상적으로 동작하게 됩니다.

---

### 요약

- **로컬 환경**: `.env` 파일 + `dotenv` 라이브러리
- **배포 환경**: **호스팅 플랫폼 대시보드**에 환경 변수를 직접 입력

이 방식을 통해 코드를 전혀 수정하지 않고, 민감한 정보를 안전하게 Git 저장소와 분리하여 애플리케이션을 배포하고 운영할 수 있습니다.
