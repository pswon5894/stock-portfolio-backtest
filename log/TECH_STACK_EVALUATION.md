# 기술 스택 (Tech Stack) 분석 및 평가

이 문서는 `stock-portfolio-backtest` 프로젝트에 사용된 기술 스택(React, Node.js/Express, MongoDB)의 장점과 단점을 분석하고, 현재 프로젝트에 대한 적절성을 평가합니다.

이 조합은 MongoDB, Express, React, Node.js의 앞 글자를 따 **MERN 스택**으로 불리며, 현대 웹 애플리케이션 개발에 매우 인기 있는 구성입니다.

---

### **MERN 스택 전체에 대한 평가**

#### **장점 (Pros)**

1.  **Full-stack JavaScript (하나의 언어)**
    -   프론트엔드(React), 백엔드(Node.js/Express) 모두 JavaScript(와 TypeScript)를 사용하므로 개발자가 언어 간의 문맥 전환 없이 전체 애플리케이션을 개발할 수 있습니다. 이는 생산성을 크게 향상시킵니다.

2.  **원활한 데이터 흐름 (JSON)**
    -   MongoDB는 데이터를 JSON과 유사한 BSON 형식으로 저장하고, Express는 JSON 형식으로 API 응답을 보내며, React는 이 JSON을 객체로 받아 UI를 처리합니다. 데이터 형식을 변환할 필요 없이 전체 스택에서 JSON이 자연스럽게 흘러 다닙니다.

3.  **거대한 생태계와 커뮤니티**
    -   NPM(Node Package Manager)을 통해 수많은 라이브러리와 도구를 쉽게 사용할 수 있습니다. React, Node.js, Express 모두 방대한 커뮤니티와 풍부한 학습 자료를 보유하고 있어 문제 해결이 용이합니다.

#### **단점 (Cons)**

1.  **비정형 데이터 관리의 어려움**
    -   MongoDB의 유연한 스키마는 장점이기도 하지만, 명확한 데이터 모델링 가이드라인 없이 개발하면 데이터의 일관성이 깨지기 쉽습니다. (예: 어떤 포트폴리오는 `initialCapital` 필드가 있고, 어떤 포트폴리오는 없는 경우)

2.  **Node.js의 단일 스레드 특성**
    -   Node.js는 단일 스레드 기반이므로, CPU 사용량이 매우 높은 계산(heavy computation)이 백엔드에서 오래 실행되면 전체 서버의 응답이 지연될 수 있습니다.

---

### **개별 기술 평가**

#### **1. 프론트엔드: React**

-   **적절성**: **매우 높음**

##### **이 프로젝트에서의 장점**

-   **컴포넌트 기반 아키텍처**: 포트폴리오 목록, 종목 추가 폼, 백테스트 결과 차트 등 UI의 각 부분을 독립된 컴포넌트로 만들어 재사용하고 관리하기 매우 용이합니다.
-   **풍부한 UI 라이브러리**: `Recharts`와 같은 차트 라이브러리나 다른 UI 컴포넌트 라이브러리를 쉽게 통합하여 시각적으로 풍부한 결과물을 만들 수 있습니다.
-   **효율적인 렌더링**: Virtual DOM을 사용하여 데이터 변경 시 UI를 효율적으로 업데이트하므로, 백테스트 결과나 포트폴리오의 실시간 변화를 부드럽게 표시하는 데 적합합니다.

##### **이 프로젝트에서의 단점**

-   **상태 관리의 복잡성**: 애플리케이션이 복잡해져 여러 컴포넌트가 상태(예: 포트폴리오 목록, 사용자 정보)를 공유해야 할 경우, React의 기본 `useState`만으로는 관리가 어려워질 수 있습니다. 이 경우 Redux, Zustand 같은 별도의 상태 관리 라이브러리 도입이 필요할 수 있습니다.

---

#### **2. 백엔드: Node.js & Express**

-   **적절성**: **높음**

##### **이 프로젝트에서의 장점**

-   **뛰어난 비동기 I/O 처리**: 외부 증권사 API에서 주식 데이터를 가져오거나, 데이터베이스에 포트폴리오를 조회하는 등 **네트워크 I/O 작업이 많은** 이 프로젝트의 특성에 매우 적합합니다. 요청을 기다리는 동안 다른 요청을 처리할 수 있어 서버 효율성이 높습니다.
-   **빠른 API 개발**: Express는 매우 가볍고 유연한 프레임워크로, 필요한 REST API 엔드포인트를 신속하게 개발하고 확장하기에 용이합니다.
-   **프론트엔드와의 언어 통일**: 프론트엔드와 동일한 언어를 사용함으로써 개발의 일관성을 유지하고, 필요 시 로직을 공유할 수도 있습니다.

##### **이 프로젝트에서의 단점**

-   **CPU 집약적 작업의 한계**: 만약 백테스팅 로직이 매우 복잡하고 방대한 데이터에 대한 순수 계산(통계, 시뮬레이션 등)으로 이루어진다면, Node.js의 단일 스레드가 잠시 멈춰 다른 API 요청 처리가 지연될 수 있습니다.
    -   *(참고: 이 문제는 `worker_threads`를 사용하거나, 계산이 많은 작업을 별도의 프로세스로 분리하여 해결할 수 있습니다.)*

---

#### **3. 데이터베이스: MongoDB**

-   **적절성**: **좋음**

##### **이 프로젝트에서의 장점**

-   **유연한 스키마**: 포트폴리오에 포함된 주식 종목들이나 백테스트의 조건들이 유동적으로 변할 수 있습니다. MongoDB는 이런 다양한 구조의 데이터를 별도의 스키마 변경 없이 쉽게 저장할 수 있습니다.
-   **JSON 친화적**: Node.js 서버에서 받은 데이터를 거의 그대로 저장하고, 조회한 데이터를 별도 처리 없이 바로 클라이언트에 전달할 수 있어 개발이 편리합니다.
-   **개발 속도**: 관계형 데이터베이스(RDB)에 비해 초기 설정과 스키마 설계에 대한 부담이 적어 빠른 프로토타이핑 및 개발에 유리합니다.

##### **이 프로젝트에서의 단점**

-   **복잡한 관계 표현의 어려움**: 만약 향후 사용자가 여러 명 생기고, 사용자들이 포트폴리오를 공유하거나, 모든 거래 내역을 정밀하게 추적하는 등 데이터 간의 **관계가 복잡해진다면** 관계형 데이터베이스(예: PostgreSQL)가 더 유리할 수 있습니다.
-   **트랜잭션의 복잡성**: 금융 관련 애플리케이션에서는 데이터의 무결성이 매우 중요합니다. 여러 데이터를 한번에 안전하게 수정해야 하는 '트랜잭션' 기능이 RDB에 비해 사용법이 다소 복잡하고 제한적일 수 있습니다.

---

### **총평**

**MERN 스택은 이 "주식 포트폴리오 백테스트" 프로젝트에 매우 적절하고 훌륭한 선택입니다.**

-   **장점**: JavaScript라는 단일 언어를 통한 빠른 개발 속도, 그리고 비동기 I/O 처리에 강한 Node.js의 특성이 데이터 기반 서비스에 잘 부합합니다.
-   **단점**: 언급된 단점들은 현재 프로젝트의 규모에서는 큰 문제가 되지 않으며, 향후 애플리케이션이 매우 복잡해질 경우에 고려해 볼 만한 사항들입니다.

결론적으로, 현재의 기술 스택은 프로젝트의 목표를 달성하는 데 있어 효율성과 확장성 측면에서 균형 잡힌 조합이라고 평가할 수 있습니다.
