  1. 데이터 유효성 검사 실패 (Validation Error) - 가장 유력

  Mongoose는 데이터를 저장하기 전에 models/Portfolio.js에 정의된 스키마 규칙에 따라 데이터가 유효한지
  검사합니다. 만약 규칙에 맞지 않으면 저장을 거부하고 catch 블록으로 에러를 보냅니다.

  Portfolio 스키마의 규칙은 다음과 같습니다.

   1 const portfolioSchema = new mongoose.Schema({
   2   // ...
   3   name: { type: String, required: true }, // 'name'은 반드시 있어야 함
   4   // ...
   5   rebalancePeriod: { type: String, enum: ['monthly', 'quarterly', 'yearly'] }, // 이 3가지 값 중
     하나여야 함
   6   // ...
   7 });

  확인해 볼 점:

   * `name` 필드가 누락되었을 가능성: 클라이언트에서 포트폴리오를 생성할 때 name 값을 보내지 않으면,
     required: true 규칙에 걸려 저장이 실패합니다.
   * `rebalancePeriod` 값 오류: 만약 rebalancePeriod 값을 보낸다면, 그 값은 반드시 'monthly',
     'quarterly', 'yearly' 셋 중 하나여야 합니다. 다른 값을 보내면 enum 규칙에 걸려 실패합니다.

  ➡️ 해결책: 서버를 실행하고 포트폴리오 저장을 시도할 때, 서버 콘솔에 제가 추가해 둔 `Request Body:
  ...` 로그가 어떻게 찍히는지 확인해 보세요. 이 로그 데이터에 name 필드가 있는지, rebalancePeriod 값이
  올바른지 확인하는 것이 문제 해결의 첫걸음입니다.

  2. 데이터베이스 연결 문제

  server/server.js 파일에서 MongoDB 연결을 시도하지만, 이 연결이 실패하면 .save() 명령은 당연히
  작동하지 않습니다.

  확인해 볼 점:

   * 서버를 처음 시작했을 때, 콘솔에 `✅ MongoDB Atlas 연결 성공!` 메시지가 나타났나요?
   * 만약 `❌ MongoDB Atlas 연결 실패` 메시지가 나타났다면, dev.js 파일의 비밀번호가 정확한지, 또는
     MongoDB Atlas에 설정된 IP 주소가 현재 환경에서 접속을 허용하는지 확인해야 합니다.

  3. 클라이언트의 요청 오류

  클라이언트(React)에서 서버로 데이터를 보낼 때, 형식이 잘못되었을 수 있습니다. 예를 들어,
  Content-Type 헤더가 application/json으로 설정되지 않으면 서버의 express.json() 미들웨어가 req.body를
  제대로 파싱하지 못하고 빈 객체 {}로 만들 수 있습니다.

  이 경우, 1번 원인과 마찬가지로 name 필드가 누락된 것으로 간주되어 저장이 실패합니다.
